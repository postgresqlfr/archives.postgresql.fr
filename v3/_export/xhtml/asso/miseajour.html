Que faire lors d'une mise à jour

Avant la sortie de la nouvelle version

Les nouvelles versions sont packagées trois/quatre jours avant la sortie. Donc il est possible d'y accéder avant leur sortie.

Avant la création du tag sur le CVS

  • Mettre à jour les .po des applications

Après la création du tag sur le CVS

  • Récupérer la nouvelle version du CVS
  • Trouver les différences entres les manuels anglais ancienne version et anglais nouvelle version
  • Ajouter le tag de l'ancienne version sur le SVN de la traduction
  • Reporter les changements sur le manuel français ancienne version
  • Finir la traduction du manuel français
  • Générer le manuel dans tous les formats disponibles pour cette version
  • Placer les fichiers sur babar, mais sans les mettre encore à disposition

Après la sortie de la nouvelle version

Manuel

  • Mettre à disposition le nouveau manuel
  • Mettre à jour la base de données de recherche
  • Mettre à jour sitemap.xml (racine de docs.postgresql.fr) avec les dates des nouvelles versions

News

  • Mettre à jour la page d'accueil (www.postgresql.fr) où sont indiquées les versions
  • Mettre à jour la page d'accueil (trac.postgresql.fr) où sont aussi indiquées les versions
  • Ajouter une news sur blog.postgresql.fr
  • Ajouter une news sur forums.postgresql.fr
  • Envoyer la news sur la liste de discussion pgsql-generale-fr
  • Modifier le topic du canal IRC #postgresqlfr
  • Rédiger une news pour linuxfr ?
