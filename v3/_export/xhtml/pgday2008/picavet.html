Voici le plan de mon lightning talk :

  1. Introduction
    1. Makina Corpus, domaines d'activités, SIG
  2. Postgresql/Postgis dans les architectures SIG web classiques
    1. environnement système
    2. outils d'intégration de données
    3. logiciels clients : langages, serveurs cartos, clients SIG lourds
    4. types d'utilisation de la Bdd dans les projets SIG web
  3. Un projet carto particulier : graphes de réseaux
    1. Contexte : deux bases de graphes de réseau routier désynchronisés
    2. Problèmatique : «recoller» les réseaux
    3. Méthodes : Sémantiques, topologiques, géométriques
    4. Type d'utilisation de postgres : «ELT», traitements longs et lourds
    5. Volumétrie des bases
    6. Environnment système : Windows
    7. Outils annexes
      1. intégration avec Talend SDI, à partir de sybase
      2. Modélisation et rétroingénierie avec PowerAMC
      3. import/export géo avec shp2pgsql, ogr2ogr
      4. clients SIG gvsig, udig (et mapinfo)
  4. Problèmes rencontrés
    1. modularisation du code en pl/pgsql
      1. compromis modularité/généricité/performance
      2. répartition du code coté client/serveur
      3. accès au log des requetes
      4. gestion du cache de requete
    2. certains traitements peu adaptés au relationnel
    3. extensions modules C sous windows
    4. paramétrages serveurs
    5. monitoring et statistiques d'exécutions (pgfouine)
    6. avancement des requetes longues
    7. gestion des tables géo selon les outils sig utilisés
    8. intégration d'outils externes pas adaptés
    9. updates
